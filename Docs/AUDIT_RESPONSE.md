### 3. ⚠️ РИСК: Discord DOM селекторы нестабильны

**Аудит указал:**
> Discord регулярно обновляет UI, селекторы ломаются без предупреждения

**✅ РЕШЕНИЕ:**
- **Fallback селекторы** (3-4 варианта для каждого элемента)
- **Remote Config:** Селекторы загружаются с сервера (можно обновлять без релиза)
- **Health Check endpoint:** Сервер мониторит работоспособность селекторов
- **Юридический disclaimer:**
  ```
  ⚠️ Discord/Midjourney автоматизация может привести к блокировке аккаунта.
  Пользователь несёт полную ответственность.
  ```
- **План действий** при поломке:
  1. Пользователь сообщает об ошибке
  2. Команда обновляет селекторы в Remote Config
  3. Расширение подхватывает изменения без переустановки
  4. Если не помогает → hotfix release

**Документация:**
- `PROJECT_SPECIFICATION.md` — раздел "ЮРИДИЧЕСКИЙ DISCLAIMER"

### 4. ⚠️ РИСК: Telegram Tribute — непроверенный провайдер

**Аудит указал:**
> Нет официальной документации этого сервиса

**✅ РЕШЕНИЕ:**
**Получена официальная документация Tribute:**
- https://wiki.tribute.tg/for-content-creators/api-documentation/webhooks
- https://wiki.tribute.tg/for-content-creators/digital-product/api-integration

**Обновлено в документации:**
- **Webhook format:** Реальная структура `new_subscription` и `cancelled_subscription`
- **Signature verification:** HMAC-SHA256 через `trbt-signature` header
- **Retry logic:** 5min, 15min, 30min, 1h, 10h
- **Idempotency:** Проверка `period_id` на дублирование
- **Currency support:** EUR подтверждён в примерах

**Реализация:**
```python
def verify_tribute_signature(request_body: bytes, signature: str, api_key: str) -> bool:
    computed = hmac.new(
        api_key.encode(),
        request_body,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(computed, signature)
```

- `PROJECT_SPECIFICATION.md` — новый раздел "TELEGRAM TRIBUTE API INTEGRATION"
- `API_SPECIFICATION.md` — обновлены webhook endpoints с реальными данными

### 5. ✅ УТОЧНЕНИЕ: Email Verification Flow

**Аудит указал:**
> Противоречие: в одном месте "не требуется", в другом "обязательна"

**✅ РЕШЕНИЕ:**
**Уточнён flow:**
1. **Регистрация на сайте:**
   - Email + Password (или OAuth Google)
   - Email verification опциональна (для безопасности личного кабинета)
   - Но НЕ блокирует использование расширения!

2. **Использование расширения:**
   - Пользователь копирует License Key из личного кабинета
   - Вставляет в расширение при первом открытии
   - Расширение валидирует ключ через API
   - Сразу открывается рабочий интерфейс
   - **Email verification НЕ требуется** для работы расширения

3. **Безопасность:**
   - License Key работает независимо от email verification
   - API валидирует ключ, а не статус email

**Обновлено:**
- `PROJECT_SPECIFICATION.md` — раздел "Authentication"
- `PROJECT_SPECIFICATION.md` — раздел "Extension (Chrome)"
